# Local v0.5 implementation contract
All JSON API; errors {error}. POST same-origin, session cookie HttpOnly SameSite=Strict; auth POST login and password APIs below. All private endpoints require session. Public /api/catalog retains original array, /api/state?operator,after sanitized queue payload, /api/settings branding settings only, /api/ticket original contract.

Auth: GET /api/me -> {user:null|{id,username,full_name,role,department,operator,must_change_password}}. POST /api/login {username,password} -> {user}; POST /api/logout {}; POST /api/password {current_password,new_password}. Demo users admin, manager, manager2, manager3, manager4, manager5, executor, head, director; password Navbot-Test-2026! (demo only --seed-demo). role values admin/manager/executor/head/director. First login demo users NOT forced password change (explicit demo); created/reset accounts must change.
GET /api/users -> {users:[{id,username,full_name,role,department,operator}]} (routing directory).
POST /api/students/search {query} -> {students:[...],more:boolean}. Authenticated staff only. Query 2–120 characters, at most 8 tokens; searches partial HEMIS ID and full name, case-insensitively, ignoring apostrophe variants. All tokens must match, in any order. Returns at most 20 students; refine the query when more=true. Does not modify students.
POST /api/student {hemis_id} -> {student:null|{hemis_id,full_name,faculty,programme,course,student_group,education_form,status},source:'local'}. Accept numeric or H-prefixed uppercase ID 6-20 ASCII chars. GET /api/students -> {students:[...]}, role admin/head/director. POST /api/students/import {students:[same fields]} admin only; transactional upsert; returns {added,updated}.
POST /api/action {operator,action:'call'|'recall'|'start'|'finish'} retains queue semantics but manager/admin only; manager limited to own operator. finish only ends physical queue; request remains separately tracked.

GET /api/requests -> {requests:[request...]}; server role scoped: manager own, executor assigned, head department + pending approvals in department, director/admin all. Each request includes id,number:'NAV-0001',ticket_id,queue_number|null,lang,section,service,student_id,student:object|null,content,note,channel:kiosk|phone,manager_id,assignee_id,department,status:new|in_progress|returned|pending_approval|closed,deadline:ISO UTC|null,internal_basis,legal_basis,answer,result,unresolved_reason,created_at,updated_at,answered_at,closed_at,version,history:[{id,actor,action,detail,created_at}],manager_name,assignee_name. Backend autogenerates one request per kiosk ticket. Queue and request states independent.
POST /api/request/create {key:UUID,channel:'phone',section,service,lang,hemis_id,identity_confirmed:true,content,note} manager/admin; no queue number for phone.
POST /api/request/action {id,version,action,...} -> {request} (optimistic version, 409 stale). Actions:
- update {hemis_id,content,note} manager owner/admin, before pending/closed
- assign {assignee_id,deadline,internal_basis,legal_basis,reason} manager owner/admin; student required, deadline future ISO w/timezone on initial assign. reassign after return must retain existing deadline/bases; reason required. can assign self to retain.
- return {reason} current executor only; manager notified, status returned, same number/deadline
- submit {answer} current assignee -> pending_approval; head notified
- approve {result} head of department or admin -> closed, needs answer
- correct {reason} head of department/admin -> in_progress, assignee notified
- resolve {answer,result} manager owner/admin with student -> close locally
- deadline {deadline,reason,internal_basis,legal_basis} head/admin only, history old/new values preserved
GET /api/notifications -> {notifications:[{id,request_id,message,read,created_at}]}; POST /api/notification/read {id} marks own.
GET /api/report?from=YYYY-MM-DD&to=YYYY-MM-DD&department=&channel=&status=&manager_id=&section=&service= -> {summary:{total,in_progress,overdue,closed,on_time},departments:[{department,total,closed,overdue}],daily:[{date,total}],requests:[...]} role head/director/admin with department scoping; CSV GET /api/report.csv same params.
GET /api/audit -> {events:[{id,actor,action,detail,created_at}]} admin only.
POST /api/admin/user {username,full_name,role,department,operator,password} -> {user}; POST /api/admin/reset {user_id,password}; POST /api/admin/settings {settings} -> {settings}; admin only.
Settings GET {settings:{university:[uz,ru,en],office:[uz,ru,en],tv_language:'uz',warning_hours:24,volume:0.75,blink_count:3,tv_titles:[[uz..],[ru..],[en..]],operator_labels:{'1':['1-operator','1-е окно','counter 1']},voice_templates:[...],catalog:original catalog, hidden_services:['0:1'],receipt_footer:[uz,ru,en]}}. Admin sets supported fields. Existing request content/bases remain snapshots. Logo upload/templates/real integration adapters may follow after core acceptance, never show false connected.
GET /api/integrations -> {lms:{connected:false},telegram:{connected:false}}. No fake external identity/notifications. In-app polling notifications only, clearly local.
UI routes /kiosk /tv /tablo public; /login /operator /manager /executor /head /director /admin /profile app shell. Links to public views. Admin settings UI, users/import, audit; reporting filters + download. User UI uses Uzbek new script as practical, localization kiosk/receipt/voice mandatory. Demo login card explicitly local test credentials.

Logo: settings.section_logos = [null|string data PNG/JPEG URL] x5. POST /api/admin/logo {section:0..4,mime:"image/png"|"image/jpeg",data:base64}, max2MiB -> {settings}. Logo values in settings save must remain unchanged (use upload endpoint).
Request update/resolve of another assignee's in-progress request rejected; return it first. Existing deadline always retained during assign/reassign. Queue state mutations advance request version for history. Ticket content is an immutable stored service-name snapshot.

## Admin extensions

- `GET /assets/i18n.js`: bundled UI localization; language/theme preferences stay in browser. Staff UI labels translate, request/user content is preserved.
- `GET /api/integrations`: **admin only**, masked metadata. `POST /api/admin/integrations {kind,url,students_url,token?,clear_token?,enabled}` saves without network. `POST .../test {kind}` explicitly checks JSON API / Telegram getMe; `POST .../sync {}` imports normalized students; no message delivery implemented.
- `GET /api/audio`: public call-clip metadata/modes. `GET /api/audio/plan?lang=uz&ticket=25&operator=3`: whole recorded call,5ordered clips, or explicit incomplete fallback. `POST /api/admin/audio/upload {lang,slot,label,mime,data:base64}`, `/delete {id}`, `/settings {lang,mode}` admin only. `/media/audio/<uuid>` serves public announcement audio. MP3/WAV max5MiB, total200MiB.
- `GET /api/report.xlsx?lang=uz|ru|en` and same report filters: scoped real XLSX with paper-style12columns and merged headers. CSV retained for compatibility.
- Request serialization includes `attachments:[{id,name,mime,size,uploader_id,uploader,created_at,url}]`. `POST /api/attachment/upload {id,version,key:UUID,name,data:base64}` appends privately, max10MiB/file,10files and50MiB/request. All visible authorized staff can upload while open. Identical retry key is idempotent; file mutation increments request version. `GET /api/attachment/<uuid>` validates current request visibility and forces download. Closed archives retain downloads but reject uploads. Files are stored in the database, never public static paths.


Section routing: settings.section_routes contains exactly five `{section:0..4,prefix:"A",operator:1..30}` entries with unique sections, uppercase letters and operators. Defaults A/1…E/5. Tickets snapshot prefix/queue_seq/target_operator at creation; POST /api/ticket and GET /api/state expose these plus code. Counters are independent per prefix. Calls select only the operator's assigned waiting tickets. Events include prefix/queue_seq; request queue_number is the real prefixed code.

Recorded layout: POST /api/admin/audio/settings `{lang,mode,layout:"numbered"|"legacy"}`. Metadata includes layouts by language. Numbered slots `intro`, `letter:A` (other configured letters supported), `number:1`…`number:500`, `operator:1`…`operator:5`. Plan GET accepts `prefix=A` and ticket is the per-prefix sequence, not database id. Numbered plan orders intro/letter/number/operator. Upload accepts optional `compact:true` for small `{saved:true,id}` responses. POST /api/admin/audio/install-pack `{}` installs the four provided UZ recordings explicitly. No existing audio is replaced on startup. Full-call slots support `call:B:25:3`; legacy `call:25:3` applies only to A.


Branding: public GET /api/branding -> {targets:[{key,label,glyph}]}. Settings.branding contains system_logo, kiosk_logo and icons keyed by target. POST /api/admin/branding {target:'system_logo'|'kiosk_logo'|'icon',key?,mime,data:base64} accepts PNG/JPEG up to2MiB; {target,key?,remove:true} restores defaults. Admin only; direct settings replacement is rejected. /media/branding/<uuid> serves image bytes; replacement/reset removes old asset. Kiosk logo falls back to system logo. Existing /api/admin/logo controls five department images.

POST /api/students/import-xlsx {data:base64} admin only, max5MiB XLSX, exact seven columns Talaba ID / To‘liq ismi / Jins / Kurs / Fakultet / Ta’lim turi / Ta’lim shakli. Returns {added,updated:0,skipped,total}. Rejects duplicate IDs, formulas and malformed rows before writing. Inserts only; existing IDs untouched. Original text fields retained in source_json; gender/education_type included in private student records. Course has numeric normalized field; original string retained. Missing programme/group remain empty, status unknown. Student files/databases are not committed.

Admin deletion: POST /api/admin/requests/delete {targets:[{id,version}],password,reason,confirm_count}. Requires admin session, current password reauthentication using persistent login-attempt limits, nonempty reason, exact count, unique target IDs and current versions. Validates all targets before mutating. Returns {deleted:N}; one transaction. Only the supplied snapshot is removed; later requests survive. Request payloads, linked attachments/history/notifications and student/staff links are purged. Minimal request/ticket ID reservations remain with deleted_at and queue status done, preventing ID reuse or replay resurrection. Private request/download APIs deny deleted data; reports and public queue events exclude deleted requests. Students/users/audio/settings/audit remain. Deletion audit contains IDs/count/reason/actor, never the password. No automatic deletion during deployment; schema7 is additive.

Profile photos: all authenticated staff may POST `/api/profile/photo` with `{mime:"image/png"|"image/jpeg",data:base64}` (2 MiB maximum) or `{remove:true}`. Returns `{avatar_url:null|string}`; `/api/me` includes the same field. The server derives the owner from the session; client user IDs have no effect. GET the returned `/api/profile/photo/<id>` URL requires the owner’s session; replaced/deleted URLs return 404. Stored in the SQLite `profile_photos` table and covered by database backups.

Admin section logo deletion: POST `/api/admin/logo` with `{section:0..4,remove:true}` clears only the selected section; kiosk falls back to its standard icon.

Admin staff lifecycle: `GET /api/admin/users` returns active/inactive accounts without secrets, including `active:boolean`; deleted accounts excluded. `POST /api/admin/user/action` accepts `{user_id,action}` where action is `update|deactivate|activate|delete`. Update requires the same username/full_name/role/department/operator fields as account creation, without password. Delete requires `confirm_username`. All are admin-only and audited. Self-deactivation/deletion and own-role change are forbidden; the last active admin cannot be removed/demoted. Open requests block deletion and role/department/operator changes. Update, deactivate and delete revoke target sessions. Inactive accounts cannot log in or receive assignments; `/api/users` lists only active accounts. Soft deletion preserves user references in historical requests and reserves the username; it clears the operator and profile image. State is stored in `user_account_states` in the existing SQLite database and included in backups.

Staff department presets use the existing role `executor` with canonical department strings `O‘quv bo‘limi`, `Xalqaro aloqalar bo‘limi`, `Xodimlar bo‘limi`, `Ma’lumotlar bazasi menejeri`. No new authorization roles. Optional `employee_number` (null or 1–20 ASCII digits as a string, preserving leading zeros) is accepted on account create/update only for executor + `Ma’lumotlar bazasi menejeri`. It is unique and independent of `operator`, which remains manager-only. Sanitized user records include `employee_number`. Startup adds the nullable users column and unique index to existing databases without changing existing accounts.

Student deletion: admin-only POST `/api/admin/students/preview` with `{ids:[hemis_id...]}` returns `{token,count,sample}` and stores a 15-minute server snapshot of exact row fingerprints. A new preview invalidates the previous one for that admin. POST `/api/admin/students/delete` with `{token,confirm_count,password}` reauthenticates using persistent login attempt limits without revoking the browser session, then validates every row before any deletion. Changed/missing targets, expired/replayed tokens return 409; no partial deletion. Later arrivals are excluded. Existing requests retain student data in `student_snapshot` and their versions increment; explicit request student updates clear that snapshot. General request purge also erases snapshots. Staff, queues, audio and settings are not changed. Deletion is audited. The student UI filters the private list and renders 50 rows per page; existing `/api/students` response remains compatible.

Student status: admin-only POST `/api/admin/students/status` with `{hemis_id,status:"active"|"inactive"}` updates only the registry flag and audits before/after. It does not delete records or change staff permissions. One-time `student_registry_migrations.initial_active_status_v1` startup migration sets current students active, then preserves all subsequent manual changes across restarts. New Excel rows default active; existing IDs remain untouched. Explicit JSON import status values are still honored.
